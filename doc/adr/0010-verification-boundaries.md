# Use Lean for semantic guarantees and source audits for architecture

Express mathematical identities and durable semantic guarantees in Lean definitions, types, and theorems. Use source architecture checks for module topology and explicit source contracts; use compiled environment audits as focused local tools for investigating elaborated API boundaries.

Declarative graphs encode allowed dependency direction, while source contracts separately encode required files or direct imports. Neither should become a catalogue of deleted paths or incidental proof syntax. The distinction permits proof refactoring while preserving the current architectural constraints.

Architecture CI protects dependency direction and exact public-boundary imports, not the continued existence of historical proof-stage directories or temporary module layouts. Keep syntax-level Python exceptions narrow and tied to a real boundary that the declarative graph cannot express, such as an umbrella sharing a prefix with its implementation subtree.

CI selects source-topology checks and compiled Lean checks independently from the changed files. Source-contract or graph tooling changes run the source audit without forcing a full library build; Lean sources and build inputs run the build and compiled correctness checks, and ordinary Lean changes exercise both paths. Advisory theorem-catalog tooling remains outside the pull-request gate, though changes to it on `main` may request a build cache for the separate Insights workflow. More declaration-specific compiled architecture investigations remain local rather than becoming permanent regression checks. Source parsing cannot establish Lean semantics, and successful elaboration alone is not a substitute for rejecting proof placeholders.

Keep generated extension declarations in the full theorem catalog as structural API, but exclude them from unresolved terminal and single-consumer review queues. The retained registry may use a full declaration name or a short name only when that base name is unambiguous. Changes to completed-result or retained-disposition notes must rerun the advisory catalog workflow so the review queues reflect their current inputs.

Audit `[simp]` registration separately from whether a theorem is useful: remove a global simp attribute when its rewrite behavior is unnecessary, but retain the ordinary theorem if it remains a meaningful endpoint. Keep private proof lemmas out of the global simp set and name them explicitly at the proof sites that need them. Delete a private simp lemma only after checking both explicit references and implicit simplifier use; a successful compiled build is needed to expose proof terms that rely on it without naming it directly. Restore such a lemma when compilation demonstrates real use.

Choose one predictable evaluation normal form per concept in the default simp set. Keep pointwise/evaluation rules as the normalizing boundary; whole-equivalence identities and symmetry facts may remain public for explicit rewriting without becoming competing global simp rules.

Treat `[simp]` as a declaration of the API's canonical normal form, not as a convenience annotation. Register computation, projection, membership, identity, and other boundary rules only when their right-hand side is clearly preferred and silent rewriting remains desirable across downstream consumers. Keep reorderings, decompositions, coordinate expansions, analytic results, and rewrites between equally natural forms explicit. Use `simp only` to pin a proof's rewrite set and `rw` for substantive transformations. A domain specialization may remain public and tagged when it is the deliberate canonical simp boundary, rather than a compatibility wrapper.

Maintain [the reviewed simp-boundary registry](../../notes/simp-boundaries.md) as the current inventory: listed Green entries are intentionally global, listed explicit-only theorems remain available for named rewrites, and unlisted global simp declarations are pending semantic review rather than implicitly endorsed. Update the registry when a reviewed boundary changes; it records current policy status, while this ADR preserves the rationale and history.

Treat the retained-theorem catalog as a current audit-exception inventory, not a permanent endorsement list. Re-audit entries when the declaration or its consumer structure changes; remove an entry when its declaration is gone or subsumed, or when the current audit no longer calls for an exception. Preserve prior reasoning in this ADR history so catalog cleanup does not rewrite the historical decision.

## Historical evidence

[Issue #2795](https://github.com/naoki-cpp/LeanCondensedMatter/issues/2795), implemented by [PR #2795](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2795), adds evaluation rules for fixed-slot linear maps to Green and records `symmetrizedProductBilinear_apply` as explicit-only. The latter exposes the bridge from the bilinear owner to pointwise notation, but is excluded from global simp to avoid a rewrite cycle.

[Issue #2791](https://github.com/naoki-cpp/LeanCondensedMatter/issues/2791), implemented by [PR #2791](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2791), updates the simp-boundary registry to state the standing policy: unlisted global simp declarations are Yellow until reviewed. The registry describes current policy rather than a dated audit milestone; the ADR retains the historical rationale.

[PR #2767](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2767) removes generated extension theorems from unresolved review queues without removing them from the full catalog, supports full-name and unambiguous short-name retained entries, and reruns advisory catalog CI when its completion/retention inputs change. These are audit-noise controls; unresolved semantic findings remain advisory rather than hard gates.

[PR #2759](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2759) completes the Yellow audit of the then-current simp set: canonical evaluation and invariant rules are promoted to Green, and four substantive identities remain explicit-only. In particular, Hall-projection-to-ordered-`xy` identities are no longer global simp rules, while direct longitudinal `sxx` record projections remain Green. Future unlisted simp declarations are still Yellow pending review.

[PR #2752](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2752) adds the reviewed simp-boundary registry, removes global simp status from eight coordinate, positivity, analytic, or boundary-value results, and keeps those results as ordinary theorems for explicit rewriting. The registry marks unlisted simp declarations pending review; it does not treat them as permanently accepted by default.

[PR #2750](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2750) expands the repository convention for simplification into an explicit normal-form policy: global `[simp]` rules must be safe canonical reductions for ordinary downstream use, while substantive or ambiguous transformations stay explicit. It distinguishes `simp`, `simp only`, and `rw`, and permits a domain-level specialization as a public simp boundary only when that is its intended canonical form. The change is documentation-only; no Lean build was run.

[PR #2598](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2598) removes a strict chain of finite-mode and finite-support evolution specializations when the only consumer can unfold the generic linearity law locally. It retains `Common.heisenbergEvolve_quarticVertexOperator` because that theorem independently states a vertex-level energy-shift eigenoperator law, and records the rationale in the retained-theorem catalog. Terminality is a review signal, not a deletion criterion; retain semantic results for their meaning, not merely their current consumer count. Current source: [retained theorem catalog](../../notes/theorem-catalog-retained.md).

[PR #2611](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2611) replaces package-umbrella imports inside the perfect-pairing package with the narrow leaf modules each decomposition uses, then re-exports those public decomposition APIs from the umbrella. Higher-level first-pair recursion remains an explicit import. This keeps internal dependency direction acyclic while preserving the intended public boundary. Current sources: [perfect-pairing umbrella](../../LeanCondensedMatter/Combinatorics/PerfectPairing.lean), [pair decomposition](../../LeanCondensedMatter/Combinatorics/PerfectPairing/PairsDecomposition.lean), and [sum decomposition](../../LeanCondensedMatter/Combinatorics/PerfectPairing/SumDecomposition.lean).

[PR #2628](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2628) adds the `replicaLinkedClusterIndependence` source-topology rule, forbidding the generic replica bridge and its Fermionic specialization from depending on cumulant inversion, connected-decomposition inversion, or the existing power-series/cumulant endpoint. This makes the alternate proof's architectural independence a checked dependency contract, while keeping theorem-catalog heuristics advisory. Current source: [source topology contracts](../../scripts/architecture/source_topology.json).

[PR #2643](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2643) recorded `Pairing.isSplit_inr` as intentionally retained at that audit, despite its then-single construction consumer: it is the canonical consequence that involutivity closes the right summand from the asymmetric left-closure premise. [PR #2678](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2678) audits simplifier surface across the repository: it deletes genuinely unused private simp lemmas, removes unnecessary global `[simp]` attributes while keeping five ordinary theorems, and inlines a one-use definitional helper. [PR #2693](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2693) trims the remaining local private simp rules, explicitly names a coefficient rewrite at its consumer, and inlines a one-use imaginary-parameter helper. [PR #2696](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2696) removes `[simp]` from public whole-equivalence identities and inverse/relabel symmetry facts while keeping the theorems available for explicit rewriting. [Issue #2099](https://github.com/naoki-cpp/LeanCondensedMatter/issues/2099) records a limit of proof-term-based terminal catalogs: absence of a direct theorem-proof reference does not establish absence of source use, because declarations can be consumed in `def` proof fields or disappear from compiled proof terms after simplification or unfolding. Use such catalogs to find review candidates; source-consumer inspection and semantic review decide whether a public declaration is redundant. This complements the compiled declaration audits without turning terminality into a deletion rule or a CI contract.

[Issue #1584](https://github.com/naoki-cpp/LeanCondensedMatter/issues/1584) replaced source-regex ownership checks with a shared Lean-environment audit for declaration ownership and namespace/module contracts, and removed the custom SecondQuantization scope parser. The enduring boundary is that Python checks files, direct imports, dependency DAGs, reachability, and source syntax only when syntax itself is the policy; compiled Lean metadata answers declaration- and type-level questions. Exact proof bodies and helper spellings are not architecture contracts. The issue's final acceptance report records a green compiled audit, but the current [architecture handbook](../../scripts/architecture/README.md) keeps declaration-specific audit tools local unless a stable invariant is explicitly selected for CI.

[Issue #1608](https://github.com/naoki-cpp/LeanCondensedMatter/issues/1608) made source-topology checks declarative and diagnostic: allowed dependency direction and reachability belong in DAGs, while required files, exact umbrella imports, and forbidden direct imports belong in separate source contracts. The shared primary graph uses non-overlapping module prefixes so Python and Lean classify layers consistently. Preserve independent graph diagnostics and keep forwarding-module checks to a narrow syntax contract; do not rebuild declaration or proof-body semantics in Python. The current [source-topology handbook](../../scripts/architecture/README.md) and [contract schema](../../scripts/architecture/source_contracts.json) record this split.

[Issue #554](https://github.com/naoki-cpp/LeanCondensedMatter/issues/554) added a permanent mode-boundary audit: foundational finite-support occupation/Fock modules may not regain `[Fintype Mode]` or `[Finite Mode]`, the root mode-label type stays assumption-free, and the unused `modeCount` declaration remains absent. The guard protects the algebraic/finite-analytic boundary instead of broadly banning legitimate downstream finite sums and Hilbert transports.

[Issue #553](https://github.com/naoki-cpp/LeanCondensedMatter/issues/553) added a repository-wide source audit for public real-valued physical definitions that directly project `.re`, while allowing proof-local extraction after a reality theorem and private implementation details. Declaration-specific exceptions require a rationale and stale exceptions fail the check; the resulting current allowlist is empty. This guard protects scalar semantics in addition to compiled theorem correctness.

[Issue #535](https://github.com/naoki-cpp/LeanCondensedMatter/issues/535) addressed `unusedArguments` under `--wfail` by omitting unnecessary `[DecidableEq]` parameters from public declarations and placing `classical` only in proofs that need equality decisions. It chose to fix the API boundary rather than suppress the warning globally, preventing unrelated full rebuilds from failing on automatically propagated instance arguments.

[Issue #525](https://github.com/naoki-cpp/LeanCondensedMatter/issues/525) treats lint exceptions as API signals to review rather than debt to delete mechanically. A targeted `unusedArguments` suppression can record an erased summability or integrability witness on a totalized function, while `simpNF` edits can change canonical rewrite behavior. Such exceptions should remain narrow and explained until the interface is deliberately changed; semantic cleanup is split by family and validated for proof churn.

[Issue #513](https://github.com/naoki-cpp/LeanCondensedMatter/issues/513) made repository-wide `lake lint` a CI gate only after clearing the existing warning baseline. It separated mechanical cleanup from semantic review: `simpNF` changes were audited because they can alter simplifier behavior, while genuinely necessary unused arguments require narrow justified suppressions. A project-wide check should be enabled after its findings are resolved, not added over a known failing baseline.

[Issue #352](https://github.com/naoki-cpp/LeanCondensedMatter/issues/352) made the architecture contract executable: Common may not depend on Fermionic or Bosonic, and Analysis/Combinatorics may not depend on SecondQuantization. The lasting guard is this present dependency graph and canonical public entry point. Checks should enforce semantic ownership and allowed layering; permanent blacklists of incidental retired paths are not the design contract.

[Issue #433](https://github.com/naoki-cpp/LeanCondensedMatter/issues/433) uses explicit low-order theorem corollaries as readable regression checks for factorial normalization, disconnected-term cancellation, and agreement between the formal and analytic linked-cluster results. Keep these checks at the public mathematical boundary so convention drift is visible in theorem statements, while the general theorem remains the source of the result.

[PR #2](https://github.com/naoki-cpp/LeanCondensedMatter/pull/2) made the absence of proof placeholders a CI requirement, explicitly tying the word “proved” to compilation without `sorry`. Its first implementation searched source text. The enduring decision is the proof-completeness requirement; the current compiled `sorryAx` audit is the relevant enforcement mechanism, so the original text-search command is not a compatibility requirement.
